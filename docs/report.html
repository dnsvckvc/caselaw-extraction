Management summary

This section is for readers who need the result and the decision, not the method. Every number in it appears again in the numbered sections, with its caveats.

What was built

The pipeline reads the 7,999 German-language civil decisions that the Swiss Federal Supreme Court published from January 2020 to October 2026. For each decision it extracts the cited statute articles, the cited leading cases (BGE), the cited file numbers, the amounts in dispute, the party roles and the outcome. It links each citation to a canonical key (the Fedlex act and article, the BGE volume and page, the normalised file number). The linked citations form a citation graph of 19,622 nodes and 86,365 edges. A read-only API serves the decisions, the citations and the three headline analyses (most-cited articles, trend by year, most central decisions) from Postgres. The same code runs on a laptop without a database in under two seconds on a 100-decision sample.

Does the choice of extractor change the result? No. The rule-based graph and the model-based graph agree on 97 to 99 percent of edges, and their top-20 lists are identical. 7.6

Decision

The rule-based extractor goes to AWS in week 4. On this corpus the learned model buys no change in any analysis at 185 times the compute. The model is kept for the cases where the rules stop: citation forms nobody has written a rule for, cantonal file numbers, and the French and Italian decisions.

Risks and limits

  • The gold set was labelled by language-model agents, not by legal professionals. One human check covers 10 of 350 decisions. The agents corrected proposals from the rules, so the gold set favours the rules in every comparison.
  • The dataset’s own outcome label disagrees with the extractor in 1,179 of 5,806 decisions. Sampling shows the dataset label is the one in error. The analyses use the extractor’s outcome.
  • The AWS costs are estimates from local run times and public price pages. Week 4 measures them.
  • Nothing is deployed yet. The Terraform stack, the image and the pipelines are written and validated; the apply waits for an AWS session and the approval of about USD 50 per month. The API runs locally on Docker Postgres.
  • The corpus is one language, one court and one branch of law. The rules do not cover French or Italian.

1. Problem

Legal professionals need to know which statutes and prior decisions a court relies on. This project extracts statute citations, prior-decision citations, header facts, amounts and outcomes from Swiss Federal Supreme Court (BGer) decisions, evaluates several extractors against a hand-labelled gold set, runs the best one over the corpus, and builds a citation graph.

2. Data

  • Source: voilaj/swiss-caselaw on Hugging Face, CC0-1.0, built by the opencaselaw project from entscheidsuche.ch. Court decisions are official works and not subject to copyright (URG Art. 5).
  • Scope for this project: BGer, German, civil-law branch (branch = 'zivil'), decisions from 2020-01-01 with full text. Corpus size: 7,999 decisions (2020-01-06 to 2026-10-07), about 1,100 per year, 25 MB as zstd Parquet.
  • Ingest: the 920 MB bger.parquet is downloaded once, then filtered with DuckDB.

Data-quality findings (week 1)

  • 13 rows tagged language = 'de' are French or Italian (all from 2026). The ingest filter now checks the text header (Arrêt du, Sentenza del) and drops them.
  • 12 rows carry chamber = 'II. Öffentlich-rechtliche Abteilung' although the text header says a civil chamber. The corpus derives chamber_text from the header instead.
  • The dataset’s outcome column is missing for 2,193 of 7,999 decisions (27%).
  • Where the dataset has an outcome, the regex extractor disagrees in 1,117 of 5,806 cases. The largest group (951 cases) is dataset = dismissed, regex = inadmissible. In every sampled case the first dispositiv item reads “Auf die Beschwerde wird nicht eingetreten” and a later item rejects a legal-aid request (“wird abgewiesen”). The dataset label appears to pick up the later item. The gold set will settle this; the working assumption is that the silver outcome label has an error rate near 16%.
  • The dataset ships its own citation graph (graph/citations.parquet, graph/statute_references.parquet). This project treats it as a silver baseline and measures it against the gold set like any other extractor.

4. Gold set

  • Target: 150 decisions (60 in week 1, 150 by end of week 2). Stratified by year and chamber.
  • Batch 1: 60 decisions, 4 or 5 per (year x chamber) stratum over 2020-2026 and the two civil chambers, text length 5,000 to 30,000 characters (ids in data/gold/batch1.ids.json). The length cap is a known bias: very long decisions are under-represented in the gold set.
  • Tool: Label Studio 1.17 in Docker with regex pre-annotation (model_version = regex-v0.1). The annotator corrects rather than draws. The first task carries 59 pre-annotations.

How batch 1 was labelled (model-labelled, three passes, adjudicated)

Batch 1 was labelled by language-model agents, not by a human. This is a weaker form of gold than human labels, and the numbers below must be read with that in mind.

  • Each agent received a decision with numbered regex pre-annotations (scripts/gold/render_task.py), wrote an edits file (delete, relabel, add by exact text), and ran a checker that refuses overlaps and unmatched text (scripts/gold/apply_edits.py). Agents never computed character offsets themselves.
  • Pass a and pass b: six Claude Fable agents each, ten decisions per agent, independent. Result: identical edits on all 60 decisions (2,650 spans, 60 outcomes). Two runs of the same model with the same brief are not independent evidence. Pass b was discarded.
  • Pass c: six Claude Opus agents, same brief. Agreement with pass a: 2,650 of 2,650 pass-a spans reproduced, 2 extra spans in pass c, outcomes 60 of 60. The two extra spans (Art. 27 Abs. 3 VSB, a banking self-regulation; Art. 93 VE-ZPO, a draft code) were dropped under the rule that STATUTE requires a law in force.
  • Rules clarified during labelling and added to the guideline: a chain of articles sharing one abbreviation is one span (also with commas, bzw., sowie, in Verbindung mit); ranges and f./ff. forms are spans; Mio. belongs to the amount; a second own docket number in joined proceedings is not a DOCKET; the outcome comes from the first dispositiv item that rules on the appeal itself, skipping side requests (Sistierung, Ausstand, legal aid); annul-and-remand and Berichtigung count as approved.
  • Final gold: data/gold/batch1.gold.jsonl, also imported into Label Studio as ground truth so that any decision can be spot-checked in the browser.
  • Batch 1 is the development set. The regex extractor was improved against it (section 6.3). Batch 2 (90 decisions, week 2) is the held-out test set. Regex v0.2 and every learned model were frozen before anyone looked at it; only regex v0.3 (section 6.6) was tuned after.

Batch 2 (week 2, held out)

  • 90 decisions, same stratification (caselaw sample --n 90 --seed 2 --name batch2), no overlap with batch 1. Pre-annotations from regex v0.2.
  • Labelled with the same toolchain: pass a (nine Fable agents), pass c (nine Opus agents), ten decisions each. Agreement a vs c: 3,571 spans in both, 0 only in a, 2 only in c; outcomes 90 of 90. Adjudication dropped Art. 90 BG (typo, unknown abbreviation) and kept F r. 30'000.00 (a sum whose currency token the text extraction broke). Final: 3,572 spans (STATUTE 1,594, BGE 1,056, DOCKET 344, AMOUNT 414, PARTY_ROLE 164); outcomes: dismissed 43, inadmissible 43, approved 2, moot 2. No partial approval occurs in batch 2, so that class is untested.
  • The agents changed little: in 68 of 90 decisions they accepted every pre-annotation. Where they edited, the causes were BGE list items after a same-volume short citation, chains with a bare Abs. element, amounts with a decimal comma, and typos in the source.
  • The agents raised 16 points the guideline does not settle. They are listed with a proposed v0.2 rule in docs/guideline-open-questions.md. Two of them change the gold set: same-volume short citations (BGE 140 III 86 E. 2, 115 E. 2, where 115 is a different decision) and Artikel written out. Both batches were labelled the v0.1 way, so the comparison below is consistent, but the citation graph (week 3) must resolve short citations separately.
  • Gold: data/gold/batch2.gold.jsonl, also in Label Studio project 1 as ground truth.
  • Human spot check (2026-10-22): Denis read 10 batch-2 decisions (seed 7 sample, ids in data/gold/batch2/spot_check.ids.json) in Label Studio with the gold spans shown. Result: 358 gold spans, 0 wrong, 0 missed; 10 of 10 outcomes right (data/gold/batch2/spot_check.md). This is the first quality number for the gold set that does not come from a model. It covers 10% of the spans in batch 2, so it bounds the error rate at roughly below 1% rather than proving zero.
  • Labels: STATUTE, BGE, DOCKET, AMOUNT, PARTY_ROLE spans; outcome as a document label.

Guideline v0.2 round (2026-10-23): four negative classes on both batches

  • Why: the learned models’ false positives were references that look like citations and are not (contract clauses, commentary article numbers, foreign law, journal references). Under v0.1 these had no span, so the models saw them only as background and the scorer could only count them as errors. v0.2 gives them classes CONTRACT_ARTICLE, BARE_ARTICLE, OTHER_LAW and JOURNAL_REF (docs/annotation-guideline.md, section “Negative classes”), so the models can learn them from data and the scorer can show the confusion. None of the four is linked.
  • How: a round over the finished batches. The task file carries the v0.1 gold as locked pre-annotations plus proposals from a wide-recall pre-annotator (negatives.py: 18 + 40 CONTRACT_ARTICLE, 22 + 40 BARE_ARTICLE, 4 + 7 OTHER_LAW, 13 + 12 JOURNAL_REF proposals for batch 1 + batch 2). Ten Fable agents (pass a) and ten Opus agents (pass c) corrected the proposals, 15 decisions each, following docs/agent-negatives-brief.md. The citation gold was not theirs to change, and no agent changed it.
  • Agreement on the negative spans: batch 1, 69 agreed, 5 only in pass a (one decision); batch 2, 100 agreed, 1 only in each pass (one decision). All citation spans and all outcomes identical in both passes.
  • Adjudication (five files under data/gold/<batch>/v2/edits/adj/): the five disputed spans of batch 1 and six agreed spans of another decision were spelled-out Ziffer ... clauses, which v0.2 leaves unlabelled until open question 6 (Artikel/Ziffer written out) is decided for all classes; the batch-2 dispute went to CONTRACT_ARTICLE with the long instrument name; two references inside a quoted party title were added as BARE_ARTICLE after a contradictory sentence in the first v0.2 draft was removed; one batch-1 span, Art. 117 GOG/ZH, was relabelled from STATUTE to OTHER_LAW (cantonal law). That relabel is the only change to the citation gold.
  • Result: data/gold/batch1.gold.jsonl (2,649 citation spans + 64 negative spans in 17 decisions) and data/gold/batch2.gold.jsonl (3,572 + 103 in 24 decisions). The v0.1 files are kept as data/gold/<batch>.gold.v0.1.jsonl. Label Studio project 1 holds the v0.2 ground truth (nine labels). The 23 guideline gaps the agents raised, and the decision on each, are in the guideline and in docs/guideline-open-questions.md (items 17 to 23).
  • Scores on the five citation classes are unchanged by the round, except that every extractor gains one span on batch 1 (the relabelled GOG/ZH is no longer a STATUTE miss).

Guideline v0.3 round (2026-10-23/24): short BGE citations and written-out forms

  • Why: Denis accepted every proposed rule in docs/guideline-open-questions.md. Two of them change the citation gold: same-volume short BGE citations (BGE 140 III 86 E. 2, 115 E. 2 → 115 is a span, question 1) and Artikel/Artikeln written out (question 6). A third extends the written-out forms to the negative classes (question 17).
  • How: the same round mechanism as v0.2 (GOLD_ROUND=v3), with proposals from regex v0.4 (which implements the two citation rules) and from the extended negative pre-annotator, on top of the locked v0.2 gold. Only decisions whose text contains one of the three patterns went to the agents: 30 of 60 in batch 1 and 46 of 90 in batch 2; the other 74 received an identity edit from the orchestrator. Five Fable agents (pass a) and five Opus agents (pass c), brief docs/agent-v3-brief.md.
  • Agreement: identical in both passes on every span and outcome of both batches (2,767 and 3,757 spans). The agents changed three proposals in total: one boundary (Ziffer 2 der Vergleichsvereinbarung), one missed short citation (155 in BGE 141 III 554, E. 2.5.1, 155 E. 4.3, found by both passes), and nothing else. No adjudication was needed.
  • Result: batch 1 gained 42 BGE, 11 CONTRACT_ARTICLE and 1 OTHER_LAW spans; batch 2 gained 59 BGE, 2 STATUTE (Artikel 104 BGG, Artikeln 35a und 35b VVG), 17 CONTRACT_ARTICLE, 3 BARE_ARTICLE and 1 OTHER_LAW. Nothing was removed. The gold is now data/gold/<batch>.gold.jsonl = v0.3 (2,767 and 3,757 spans); v0.1 and v0.2 are kept beside it (*.gold.v0.1.jsonl, *.gold.v2.jsonl). Label Studio holds the v0.3 ground truth.
  • Open cases the agents raised and the rule now applied: a lone Absatz 2 referring back to a statute, a lone Ziffer 1 Absatz 2 of a settlement named earlier, Randziffer 26 of a brief, Dispositivziffer 1-4 of an authority’s order: no span (a reference needs Art., Artikel or § for BARE_ARTICLE, and points of court or authority documents and briefs are never spans).
  • Entity level: a short citation’s key is resolved from the nearest full citation before it (evaluate.bge_key), both in the scorer and in the linking stage, so 115 after BGE 140 III 86 links to BGE 140 III 115.

Batch 3 (2026-10-25 to 2026-10-28): 200 decisions, half of them targeted

  • Why: the learning curve (6.12) said the span models gain about 0.002 F1 per 15 random decisions beyond 60, and the negative classes and rare outcomes have too few examples to be learned at all. Denis asked for 200 more decisions. Random sampling would supply contract clauses at about 0.6 per decision and partial approvals at 2 per 100, so half of the batch was drawn on purpose.
  • Sampling (caselaw sample --n 200 --targeted 100 --seed 3, sample.pick_targeted): 100 decisions from the unused civil-chamber pool (4,101 decisions of 5,000 to 30,000 characters) that match a rare-class pattern or a rare outcome, with quotas filled from the rarest group up: foreign law 15, partial approval 15, moot 8, approved 27, contract clauses 36, journal references 36 (a decision can count for several groups; data/gold/batch3.groups.json). The other 100 are stratified by year and chamber like batches 1 and 2.
  • Pre-annotation: regex v0.4 for the citation classes and the negative-class pre-annotator in one task file (labelstudio.to_task), 10,101 proposals, about 50 per decision.
  • Labelling: two windows of 100 decisions, each with ten Fable agents (pass a) and ten Opus agents (pass c), ten decisions per agent, brief docs/agent-labelling-brief.md (v0.3 edition, nine classes). The windows were separated by a usage-limit reset; a credit cut-off stopped ten Fable agents of the second window part-way, and three fresh agents finished the 27 missing decisions two days later. Nothing was lost: every finished decision is a file.
  • Agreement over the 200 decisions: 10,230 spans agreed, 22 only in pass a, 28 only in pass c (F1 0.998); outcomes 200 of 200 identical. The 50 disputed spans in 14 decisions were adjudicated by me (data/gold/batch3/edits/adj/); the new rules they needed are in the guideline under “Clarifications from batch 3” (bracketed corrections inside a reference, und/oder as a joiner, foreign currency words, yearbooks and newsletters, quoted clause headings, treaties named by a short title).
  • What the targeted half exposed in the pre-annotator: cantonal abbreviations cut after EG (EG ZPO/GL), contract clauses cut at the first number (Art. 36 for Art. 36.2 AVB), the revised judgment’s file number missed in revision cases (5A_89/2020, 20 mentions), amounts cut inside the number (Fr. 100 for Fr. 1000.--), and Reglement/Verordnung with an SR number proposed as CONTRACT_ARTICLE. The agents corrected all of these.
  • Result: data/gold/batch3.gold.jsonl, 10,259 spans (STATUTE 4,161, BGE 2,672, AMOUNT 1,462, DOCKET 1,059, PARTY_ROLE 376, CONTRACT_ARTICLE 223, BARE_ARTICLE 124, JOURNAL_REF 98, OTHER_LAW 84), outcomes dismissed 75, inadmissible 70, approved 29, partial approval 17, moot 9. The gold set is now 350 decisions. Label Studio project 1 holds all 350 as ground truth.
  • Regex v0.4 against batch 3 (its own pre-annotations corrected): span F1 0.991, recall 0.983, outcome 194 of 200. This is the lowest regex number in the report, because the targeted half contains the forms the rules do not cover (5D_ dockets, lit a without the dot, GebV SchKG, line breaks inside citations) and because batch 3 is not a random sample.
  • Annotation guideline: docs/annotation-guideline.md.

Since 2026-10-23 every extractor’s output goes through one more stage, entity linking (caselaw link, src/caselaw_extraction/linking.py): STATUTE spans are resolved to a Fedlex act and article, BGE spans to BGE volume part page, DOCKET spans to a normalised file number; a span that resolves to nothing (a code that is not a federal act, a BGE fragment, the decision’s own file number) is dropped. The stage holds the two facts no span model can read from the text, the Fedlex list and the own file number, and it applies to the regex and the LLM exactly as to the learned models. It never moves a boundary and never adds a span. Scores are reported before and after linking (section 6.8), so that a learning failure that the linking removes stays visible in the “before” column.

All extractors write the same prediction format (data/pred/<batch>/<name>.jsonl) and are scored by one command (caselaw score <file> --batch batch2 --name <run>), which also logs parameters, metrics and the prediction file to MLflow (sqlite:///mlflow.db, experiment caselaw-extraction). 6.7 What the learned models would need to beat the rules

  • Labels: 60 decisions give 2,650 spans but only 60 outcome labels in four classes. The outcome classifiers are data-starved; 500 agent-labelled outcomes would cost about an hour.
  • Knowledge the text does not contain: the Fedlex abbreviation list and the decision’s own file number. These now live in the entity-linking stage (section 6.8), which every extractor passes through. They are architecture, not a model improvement, and the report does not count them as one.
  • Learning failures that the linking stage must not hide: commentary references (N. 6 zu Art. 242), contract clauses (Art. 13 Ziff. 2 lit. a AVB) and fragments (Art, 8). Guideline v0.2 gives the first two their own classes so the model can learn them and the scorer can show the confusion (section 6.10); the fragments are a decoding matter (6.9).
  • Where they could win: text the regex has not seen (new citation forms, broken tokens such as F r. 30'000.00, which gbert found and the regex did not) and languages (the French and Italian decisions are out of scope of every rule written so far).

6.9 Decoding: argmax vs BIO-constrained Viterbi (gbert, batch 2)

The token classifier predicts each token independently, so O, I-STATUTE sequences occur. A Viterbi pass over the same logits with hard BIO constraints (no learned transitions, no retraining; transformer_extractor.viterbi_decode) is the principled fix for invalid sequences. Result: +0.001 to +0.002 span F1 on every seed (s0 0.984 → 0.986, s1 0.983 → 0.985, s2 0.986 → 0.986), DOCKET gains most (0.962 → 0.963/0.969). Most fragments the model emits (Art, 8) are valid BIO sequences, so the constraint rarely fires. A CRF head or more training data would be the next step; neither is done.

The two graphs are the same graph for every question this report asks. The 20 most-cited articles are the same 20 in the same order. The 20 most central nodes are the same 20 (the first two swap places: PageRank puts BGE 142 III 364 first in the gbert graph and BGE 140 III 115 first in the regex graph, with 3,170 against 3,348 citing decisions). The trend tables differ in the second decimal. The outcomes agree on 7,840 of 7,999 decisions; the model fills the 52 decisions the rules leave unknown, and the largest disagreement (65 decisions, rules dismissed, model inadmissible) is the same formula problem as between the rules and the dataset label. Against the dataset label the two extractors agree equally often (4,627 and 4,611 of 5,806).

Where they differ, the samples show both sides. The gbert-only BGE citations are real citations written without the BGE prefix or across a line break that the regex does not accept (BGE 119 II 249, BGE 137 III 4). The gbert-only file numbers include cantonal and foreign numbers that the regex pattern excludes on purpose (13Y_2_2021, O2017_025, B25_96): the linking stage normalises a file number but does not know which courts exist, which is a week-4 item for the statute-like lookup table of courts. The regex-only file numbers are mostly 5D_ numbers of joined proceedings, rare in the training data even after the targeted batch. The regex-only statute citations are the long chains where the model cut a span short (BGG 66 at the end of a costs chain) and codes the model never saw (BauAV, FINMAG). The linking stage dropped 3,463 model spans and one regex span: 2,264 model spans named a code that is not a federal act (contract clauses and cantonal acts the model still labels STATUTE in a small share of cases, see 6.13), and 810 were the decision’s own file number, which no span model can know (section 6.8). The model also labelled 10,119 spans in the four negative classes (contract clauses 2,693, bare article numbers 3,539, other law 1,504, journal references 2,383), which the regex does not produce; they are kept in the spans table and are not citations.

The deployment decision follows: the rules go to AWS. On this corpus the learned model buys an agreement of 0.99 with itself at 185 times the single-process compute (30 minutes on a GPU against 10 seconds on one core) and no change in any analysis. The model’s value is elsewhere: it is the extractor that reads the forms the rules do not list (the prefix-less BGE, the cantonal file numbers), it measures the rules on 7,999 decisions instead of 350, and it is what the pipeline will need for the languages and courts for which nobody has written the rules yet.

8.3 Drift check

caselaw drift (drift.py; GET /drift, GET /drift/series) compares the entity-frequency distributions of two periods of decision dates, months or years. For the citation kinds the distribution is the number of decisions that cite each key (article, BGE, file number, act); for the outcome, decisions per class; for the span labels, spans per class. Two periods are compared with the Jensen-Shannon distance (0 identical, 1 disjoint) and the total variation distance, and the keys whose share of decisions moved most are listed. The check runs on DuckDB and on Postgres with the same SQL, so it works on a laptop against a run directory and in the cloud against RDS.

A threshold needs a noise level, so the series over the 81 month-to-month steps of the corpus comes first (caselaw drift --series):

kind median JS distance 95th percentile maximum usable month to month?
statute article 0.448 0.491 0.515 yes; about 250 distinct articles per month of 100 to 150 decisions, so the tail is noisy and the level is high
act (code) 0.227 0.278 0.322 yes, the most stable citation signal
BGE 0.620 0.669 0.682 marginal; 300 to 450 distinct leading cases per month
outcome 0.140 0.225 0.273 yes
file number about 0.93 – – no; file numbers rarely repeat between months

The proposed rule is one alarm per kind at the 95th percentile of its own series (statute 0.49, act 0.28, outcome 0.23), with caselaw drift --fail-above as the check. The last complete step, August to September 2026, stays under every threshold (statute 0.445, act 0.230, outcome 0.169), and it is still the step the check points at: the number of distinct articles halves (230 to 134), the share of inadmissibility rulings rises from 67 to 76 percent, the share of decisions citing the ZPO falls from 31 to 7 percent, and BGE 140 III 115 and 142 III 364, the two substantiation precedents, gain 9 and 12 points. The decisions themselves explain it: the mean text length of a September 2026 decision is 6,900 characters against 10,700 in August and 11,000 to 13,000 in spring, and spans per decision drop from 30 to 20. Either the court’s September output was unusually short, or the dataset’s most recent month is not complete yet and the long decisions arrive later; the next dataset release will tell. This is what the check is for: it names the month and the keys, and a reader with the texts can decide.

9. What did not work

Running log.

  • 2026-10-20: timeout is not available on macOS by default; use the tool timeout instead.
  • 2026-10-20: Label Studio 1.17 rejects legacy API tokens by default. The helper in scripts/labelstudio_api.py logs in through the session form instead.
  • 2026-10-20: DuckDB Python UDFs need numpy; chamber normalisation moved into SQL.
  • 2026-10-21: two independent passes of the same model (Fable) with the same brief produced byte-identical edits on all 60 decisions. A second pass only adds information with a different model.
  • 2026-10-21: agents cannot compute character offsets reliably. Letting them name spans by exact text and resolving offsets in a checker worked on the first try for all 180 agent-decisions.

  • 2026-10-20: the first dispositiv pattern only matched “Demnach erkennt das Bundesgericht” and left 54% of outcomes unknown. Single-judge rulings use “der Präsident”, “die Präsidentin”, “das präsidierende Mitglied”, “der Einzelrichter”, and short rulings drop “Demnach” entirely.

  • 2026-10-21: transformers 5 cannot load deepset/gbert-base through AutoTokenizer or AutoConfig (vocab.txt-only checkpoint without model_type). BertTokenizerFast and BertConfig load it; the extractor falls back to them.

  • 2026-10-21: the dataset’s silver graph stores BGE citations under match_type = docket_norm; only the target_decision_id prefix (bge_, bger_) tells the two apart. Reading it by match type gave a docket precision of 0.42; reading it by target prefix gives 0.996.
  • 2026-10-21: the guideline example “a second page number is not a span” (BGE 140 III 86 E. 2 S. 89, 115 E. 2) is factually wrong in most occurrences: 115 is BGE 140 III 115, a different decision. Every agent followed the example and flagged it. Both batches are therefore consistent and both miss these citations. Logged as question 1 in docs/guideline-open-questions.md.
  • 2026-10-21: the LLM agents wrote BGE list items in the bare form (140 III 86) even where the text has BGE 140 III 86, because the prompt showed the bare form for continuation items. The resolver now restores the prefix. A prompt example shapes output form more than a rule does.
  • 2026-10-23: a post-filter on model output (Fedlex list, own docket, BGE shape) raised gbert from 0.984 to 0.992 in an afternoon. It was not added as a model improvement, because it hides learning failures and because its rules were designed by reading the batch-2 errors. It became the entity-linking stage that every extractor passes through (section 6.8), with before/after reported, and the hidden failures became classes (guideline v0.2).
  • 2026-10-23: Fedlex keys the European Patent Convention as EPÜ 2000, with the year. The regex, the entity-key parser and the first draft of the linker all stripped the year before the lookup, and the regex’s code pattern tried a single digit before a four-digit year. Three gold spans were lost to this in every extractor that uses the list.
  • 2026-10-21: pass a (Fable) and pass c (Opus) agreed on 3,571 of 3,573 spans in batch 2, as in batch 1. Two different models with the same brief and the same pre-annotations are not two independent annotators either; the pre-annotation anchors both. The human spot check (section 4) is the only independent signal available; it found no error in 358 spans.
